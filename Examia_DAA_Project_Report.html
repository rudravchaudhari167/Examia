1. Problem Statement & Objectives

1.1 Problem Statement

In academic institutions, scheduling end-semester examinations is a high-dimensional combinatorial challenge. Given a set of courses, student cohorts enrolled across multiple overlapping subjects, and a finite pool of physical classrooms, manual timetable generation is notoriously prone to severe human errors. These errors include:

  • Student Clashes: Scheduling two exams simultaneously when one or more students are enrolled in both.
  • Room Double-Booking: Allocating the same physical exam hall to multiple courses in the same time slot.
  • Capacity Violations: Allocating an examination hall whose physical seating capacity is lower than the registered student count.

Formally, the Examination Timetabling Problem is isomorphic to the Graph Vertex Coloring Problem, proven to be NP-Complete (Karp, 1972). A brute-force search over m slots and V courses requires O(mV) evaluations, making automated algorithmic solutions mandatory.

1.2 Project Objectives

  • Zero-Conflict Hard Constraint: Model subjects as vertices and shared student enrollments as undirected edges such that adjacent vertices never share identical examination time slots (graph colors).
  • Time Slot Minimization: Optimize slot count toward the graph's Chromatic Number χ(G).
  • Algorithmic Dual-Strategy: Implement both a polynomial-time heuristic (Welsh-Powell Greedy Coloring) and an exact constraint solver (Recursive Backtracking Coloring).
  • Greedy Classroom Allocation: Automatically assign physical rooms using a capacity-aware Best-Fit bin-packing heuristic with multi-room splitting for large courses.
  • Production Architecture: Provide a complete 3-tier web platform using Java 21 LTS Standard Library backend, SQLite in WAL mode, and a React 18 Single-Page Application.

3. Selected DAA Strategy & Algorithms

Examia formulates the timetabling domain into an undirected graph G = (V, E):

  • Vertices (V): Each subject is a vertex v ∈ V.
  • Edges (E): An edge (u, v) ∈ E exists if and only if EnrolledDivisions(u) ∩ EnrolledDivisions(v) ≠ ∅.
  • Colors: Non-negative integers representing discrete calendar examination time slots.

3.1 Algorithm 1: Welsh-Powell Greedy Graph Coloring

Standard greedy coloring processes vertices arbitrarily, which often inflates slot usage. Welsh and Powell (1967) introduced the degree-ordering heuristic: vertices with higher degrees have the most conflicting neighbors and are the hardest to color. Sorting vertices by descending degree ensures high-conflict vertices are assigned slots early when choices are unconstrained, while low-degree vertices easily reuse slots later.

3.2 Algorithm 2: Recursive Backtracking Coloring (m-Coloring)

Backtracking explores the state-space decision tree using Depth-First Search (DFS). For each subject, candidate slots from 0 to m-1 are evaluated using an isSafe() check. If a candidate slot conflicts with an already-colored adjacent neighbor, the branch is pruned immediately. If all slots fail for a child node, the algorithm backtracks, unassigns the slot, and tries the next branch. Incremental search (k = 1, 2, 3...) guarantees finding the minimal Chromatic Number χ(G).

4.2 Pseudocode: Welsh-Powell Greedy Coloring

ALGORITHM WelshPowellGreedy(G = (V, E)):
    FOR EACH v IN V: degree[v] ← count(G.neighbors[v])
    Sort V descending by degree[v]
    assignments ← empty map
    FOR EACH u IN sorted_V:
        used_colors ← { assignments[w] | w ∈ G.neighbors[u] ∧ w ∈ assignments }
        c ← 0
        WHILE c ∈ used_colors: c ← c + 1
        assignments[u] ← c
    RETURN assignments

4.3 Pseudocode: Recursive Backtracking Coloring

FUNCTION Backtrack(G, subjects, index, m, assignments):
    IF index == length(subjects): RETURN TRUE    // Base condition
    u ← subjects[index]
    FOR slot ← 0 TO m - 1:
        IF isSafe(u, slot, G.neighbors[u], assignments):
            assignments[u] ← slot                  // Tentative move
            IF Backtrack(G, subjects, index + 1, m, assignments): RETURN TRUE
            REMOVE assignments[u]                  // Backtrack step (undo)
    RETURN FALSE

5. Implementation Details

5.1 Software Architecture

Examia is designed with a lightweight, decoupled 3-tier architecture with zero third-party framework overhead:

  • Backend Server (Java 21 LTS): Implemented using the standard library com.sun.net.httpserver.HttpServer with an asynchronous ThreadPoolExecutor. It provides REST JSON APIs on port 8080.
  • Persistence Engine (SQLite WAL Mode): Self-contained examia.db configured with Write-Ahead Logging (WAL) for thread-safe concurrent reads and writes. Core tables include subjects, student_groups, subject_enrollments, classrooms, and algorithm_runs.
  • Decoupled Utility Package: Core JSON serializing and deserializing is isolated in com.examoptima.util.JsonHelper, eliminating circular dependencies between server, database, and service layers.
  • Classroom Bin-Packing: Handled by ClassroomAllocationService. For each time slot, active physical rooms are cloned into an available pool. Subjects are assigned rooms using Best-Fit capacity sorting, preventing room double-booking and ensuring seating sufficiency.
  • Frontend SPA (React 18 + Tailwind CSS): Fast single-page client providing dynamic timetable generation, conflict graph visualizers, room breakdown accordions, and print-ready schedules.

6. Time & Space Complexity Analysis

6.1 Mathematical Derivations

1. Conflict Graph Construction Complexity

Pairwise testing across all V courses checks &binom;{V}{2} = rac{V(V-1)}{2} = Θ(V2) pairs. For each pair, checking intersection of student divisions takes O(D2) time, where D ≤ 4 is constant. Total Time: Θ(V2). Space: O(V + E) for adjacency lists.

2. Welsh-Powell Greedy Coloring Complexity

Sorting V vertices by degree takes O(V log V). In the coloring loop, inspecting neighbor colors across all vertices evaluates every edge twice (∑ deg(u) = 2E). Finding the minimum unused color using a hash set takes O(deg(u)). Total Time: O(V log V + E). Space: O(V) for assignments and sets.

3. Backtracking Coloring Complexity

The state-space tree has depth V and branching factor m. In the unpruned worst-case, it explores mV leaf nodes. Safety checks per node take O(V). Total Time: O(V × mV) (Worst Case) and Ω(V) (Best Case). Space: O(V) for the call stack.

7. Conclusion & Future Scope

7.1 Conclusion

Examia delivers an automated, mathematically verified, and computationally optimal solution to the NP-complete Examination Timetabling Problem. By converting student division overlaps into conflict graph edges, the system guarantees zero examination clashes. For real-time institutional operations, Welsh-Powell greedy coloring produces compact schedules in under 10 milliseconds. For academic benchmarking, backtracking search guarantees minimal chromatic slot utilization. Coupled with capacity-aware classroom allocation and SQLite WAL persistence, the project represents a robust implementation of core DAA strategies.

7.2 Future Scope

  • Faculty Invigilator Assignment: Formulating invigilator scheduling as a Maximum Bipartite Matching problem (Hopcroft-Karp algorithm) to balance faculty duty hours.
  • Metaheuristic Soft Constraints: Integrating Genetic Algorithms (GA) to ensure students receive study gaps between consecutive heavy examinations.
  • Multi-Campus Geographic Constraints: Modeling travel transit times between disparate satellite campuses to prevent impossible transit windows.
